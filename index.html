What CmDarri does

Practical software, built to be affordable

CmDarri exists to ship software that solves a real, narrow problem well, and to charge a price that does not make a small tool unaffordable.

Every current application follows the same shape. A converter that batches an entire folder of videos instead of one file at a time. A timelapse tool that understands a sequence of photographs taken months apart, rather than assuming the input is shaky video. An AI assistant that keeps the model and the conversation on the device, so the app is useful on a flight or in an area with no signal.

Where an app can work without a server, it does. That is a product decision as much as a technical one: local processing is faster, works without a connection, and removes an entire category of data handling.

CmDarri is currently a small development team. Projects are built, released and supported by the same people, and the published privacy policies describe what each app actually does with your data rather than a generic template.

Development principles

  • 01 · On-device firstLocal processing wherever the hardware allows
  • 02 · Offline capableNo connection required for core features
  • 03 · Plain privacy termsPolicies written per app, not copied boilerplate

How an app gets made

From idea to published build

  1. 01

    Identify the problem

    Start from a specific, repeated annoyance rather than a feature list. If the task cannot be described in one sentence, it is not scoped yet.

  2. 02

    Build the core

    Implement the part that makes the app worth installing first, then hold the interface to a standard the app can live up to.

  3. 03

    Test on real devices

    Run it on the hardware people actually own, including older models, and check the behaviour when the network, storage or battery is against it.

  4. 04

    Publish and document

    Ship only what is finished, list only the features that exist, and publish the privacy policy for the app as it actually behaves.
